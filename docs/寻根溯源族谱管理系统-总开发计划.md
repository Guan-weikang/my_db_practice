# 寻根溯源族谱管理系统总开发计划

## Summary

- 目标：按“课程作业可验收 + 项目可运行”双标准推进，覆盖功能实现、复杂查询、数据规模、性能验证、部署演示和提交材料。
- 当前状态：前后端目录骨架已齐全，数据库主表与索引已落地；后端路由、服务和前端页面大多仍是骨架或占位实现。
- 组织方式：采用“基础到验收”的阶段推进法，先收口工程基线与权限，再完成业务能力、复杂查询、数据与性能，最后统一做联调、部署和材料交付。
- 交付节奏：本次只产出总计划；后续按阶段分别展开详细计划文档、任务拆解和实施。

## Key Interfaces

- 后端以 `/api/v1` 为统一前缀，按 `auth`、`users`、`family-trees`、`collaborators`、`members`、`relationships`、`search`、`analytics`、`kinship`、`health` 十个模块落地。
- 前端以登录/注册、Dashboard、族谱列表/详情、协作者管理、成员列表/详情、祖先查询、亲缘路径查询为主页面集合。
- 数据与离线能力必须纳入正式范围：模拟数据生成、CSV 导入导出、性能对比 SQL、执行计划分析、数据库导出文件和实验报告材料。

## Phases

### 1. 阶段一：工程基线与开发环境收口

任务：

- 统一配置项、环境变量、数据库迁移基线、日志、健康检查、错误响应结构、分页约定、测试基座和本地启动说明。

验收标准：

- 前后端可独立启动。
- 数据库可一键迁移。
- `/api/v1/health` 可用。
- 基础配置文档与启动命令稳定。

测试：

- 后端启动冒烟测试。
- 数据库连接与迁移测试。
- 前端构建测试。
- 健康检查接口测试。

### 2. 阶段二：认证与权限闭环

任务：

- 实现注册、登录、刷新令牌、登出、当前用户信息。
- 落地 JWT Access/Refresh Token、Argon2 密码哈希、认证依赖和基于族谱角色的权限检查。

验收标准：

- 受保护接口必须校验登录态。
- 刷新令牌可续期。
- 登出后刷新令牌失效。
- 未授权/越权请求返回统一错误。

测试：

- 认证服务单元测试。
- 登录刷新登出 API 测试。
- 权限拒绝场景测试。
- 前端路由守卫与登录状态恢复测试。

### 3. 阶段三：族谱与协作者模块

任务：

- 完成族谱 CRUD、可访问族谱列表、协作者邀请/修改角色/撤销权限。
- 明确 `creator`、`collaborator`、`reader` 的读写边界。

验收标准：

- 用户只能看到自己创建或被授权的族谱。
- 创建者可管理协作者。
- 协作者可维护内容但不可删谱。
- 只读用户不可修改数据。

测试：

- 多用户可见范围测试。
- 协作者角色切换测试。
- 越权修改测试。
- 列表与详情接口联调测试。

### 4. 阶段四：成员与关系维护

任务：

- 完成成员 CRUD、父母子女关系维护、婚姻关系维护。
- 补齐成员生命周期约束、父母早于子女等业务校验。
- 把数据库约束与接口校验统一。

验收标准：

- 成员信息可完整维护。
- 非法关系、重复关系、自环关系、跨族谱关系和违反出生顺序的数据都被拒绝。
- 删除和更新行为规则明确。

测试：

- 模型约束测试。
- 关系 API 测试。
- 异常输入测试。
- 祖先环路触发器测试。

### 5. 阶段五：搜索、树形预览、祖先查询与亲缘路径

任务：

- 实现姓名模糊查询、分支树形预览、成员祖先递归查询、两人亲缘路径查询。
- 完成前端基础展示。

验收标准：

- 重名成员可区分。
- 树形结果能反映上下代结构。
- 祖先查询支持不固定深度。
- 亲缘路径查询可返回存在性与链路结果。

测试：

- 原生 SQL/CTE 查询测试。
- 代表性家谱样例测试。
- 查询接口测试。
- 前端结果展示与空结果场景测试。

### 6. 阶段六：Dashboard 与统计分析

任务：

- 实现总人数、男女比例以及课程要求的三类统计 SQL。
- 统一结果结构。
- 视情况加入轻量缓存。

验收标准：

- 统计结果与数据库真实数据一致。
- 所有课程要求 SQL 可单条执行并可复用到接口。
- 接口返回可直接支撑 Dashboard 页面。

测试：

- 查询层结果校验测试。
- 聚合边界值测试。
- 接口响应测试。
- 前端 Dashboard 联调测试。

### 7. 阶段七：模拟数据、导入导出与性能优化

任务：

- 编写数据生成脚本，满足 10 个族谱、至少 1 个 5 万成员族谱、总量不少于 10 万成员、至少 30 代传承。
- 实现 CSV/COPY 导入、分支数据导出、索引与性能验证。

验收标准：

- 数据规模达标。
- 导入导出流程可复现。
- 姓名模糊查询和四代查询能完成索引前后对比，并产出 `EXPLAIN ANALYZE` 结果。

测试：

- 小规模脚本正确性测试。
- 全量数据计数校验。
- 导入导出完整性测试。
- 性能基准复测。

### 8. 阶段八：前端联调与交互收口

任务：

- 补齐页面表单、列表、详情、查询页、权限提示、加载/错误/空状态、基础样式与导航流转。
- 使主要功能形成可演示闭环。

验收标准：

- 从登录到查谱、管谱、查成员、查祖先、查亲缘、看统计的主流程可连续演示。
- 前端权限表现与后端一致。
- 关键页面无阻塞性缺陷。

测试：

- 前端路由与状态流测试。
- 接口联调测试。
- 关键用户流程手工验收测试。

### 9. 阶段九：部署、观测与课程交付收尾

任务：

- 完善 Docker Compose 与可选 Nginx 部署。
- 完善日志与健康检查。
- 准备数据库导出文件、实验报告素材、SQL 执行截图、演示清单和答辩脚本。

验收标准：

- 项目可在演示环境稳定启动。
- 提交物完整覆盖需求文档列出的材料。
- 演示流程与答辩问题有对应证据。

测试：

- 部署冒烟测试。
- 容器启动验证。
- 提交物清单核对。
- 最终全链路回归测试。

## Test Plan

- 测试分层固定为：后端 `api/services/queries`、前端页面与状态联调、数据库约束/查询验证、离线脚本验证、最终演示回归。
- 每个阶段至少包含一组成功路径、一组权限/约束失败路径、一组边界数据路径，避免只验证 happy path。
- 从阶段四开始建立稳定测试数据集；阶段七再扩展到性能基准数据集，避免功能测试与性能测试相互污染。
- 所有课程要求 SQL 都必须同时具备：可独立执行版本、接口调用版本、结果截图版本、性能分析版本。

## Assumptions

- 继续沿用现有技术栈：FastAPI + SQLAlchemy 2.0 + Alembic + PostgreSQL + Redis + Vue 3 + Vite + Pinia + Axios。
- 现有数据库迁移与表结构作为正式起点，后续若补充跨表约束或字段调整，通过 Alembic 增量迁移处理，不回退为手工改库。
- 计划默认把“课程交付物”视为正式开发范围，而不是项目结束后的附加整理工作。
- 详细阶段计划文档后续按本总计划逐阶段展开，默认每阶段都要进一步细化为任务清单、接口清单、数据准备、测试用例和完成定义。
