# 阶段四：成员与关系维护详细执行与测试验收文档

## 1. 文档目的

本文档用于细化《[寻根溯源族谱管理系统-总开发计划](/home/mochen/db_practice/docs/寻根溯源族谱管理系统-总开发计划.md)》中的“阶段四：成员与关系维护”，作为阶段四实施、联调与验收的直接依据。

本文档默认承接以下前提：

- 阶段一已固定统一错误结构、分页结构和测试基座。
- 阶段二已完成登录鉴权与 `creator` / `collaborator` / `reader` 权限依赖。
- 阶段三已完成族谱 CRUD、协作者管理以及“所有已登录用户默认可读族谱”的访问基线。

## 2. 阶段目标

本阶段的目标是让“成员”成为族谱中的正式业务对象，并为后续阶段的搜索、树形预览、祖先查询、亲缘路径与统计分析提供稳定的数据入口，具体包括：

- 完成成员 CRUD。
- 完成父母子女关系维护接口。
- 完成婚姻关系维护接口。
- 明确成员生命周期校验与关系校验边界。
- 统一数据库约束、服务层校验与接口层返回行为。
- 建立阶段四稳定测试数据，为阶段五起的复杂查询模块复用。

## 3. 范围与边界

### 3.1 本阶段范围

- 成员列表、详情、创建、修改、删除
- 父母子女关系创建、删除、读取
- 婚姻关系创建、更新、删除、读取
- 成员基础字段校验
- 出生日期先后校验
- 祖先环路拒绝验证
- 阶段四测试数据、自动化测试与手工联调说明

### 3.2 本阶段不做

- 不实现姓名模糊搜索
- 不实现分支树形预览
- 不实现祖先递归查询和亲缘路径查询
- 不实现 Dashboard 统计分析
- 不引入成员或族谱软删除
- 不扩展“非空族谱删除”规则

## 4. 阶段四固定业务规则

- 延续阶段三基线：所有已登录用户默认可读取族谱，因此也默认可读取该族谱下的成员与关系。
- `creator`、`collaborator` 可以创建、修改、删除成员和关系。
- `reader` 与未显式授权但已登录用户只能读取成员与关系，不可修改。
- 成员删除采用物理删除。
- 阶段四不引入成员恢复流程。
- 阶段四保留婚姻生命周期字段，因此婚姻关系除 `POST`、`DELETE` 外，补充 `PATCH` 正式维护 `married_at`、`ended_at` 与 `status`。

## 5. 交付物

本阶段完成后，至少应产出以下成果：

1. 可用的成员 CRUD 接口
2. 可用的父母子女关系接口
3. 可用的婚姻关系接口
4. 已落地的成员与关系权限边界
5. 前端成员列表与成员详情最小演示页面
6. 阶段四稳定测试数据脚本与说明
7. 阶段四 API 测试、约束测试与手工验收用例
8. 更新后的阶段四执行文档与联调说明

## 6. 详细执行任务

## 6.1 工作包 A：成员与关系接口契约收口

目标：

- 在实现前固定阶段四接口、请求响应模型、角色边界与删除规则，避免实现过程中反复改动。

具体任务：

- 固定成员接口：
  - `GET /api/v1/family-trees/{tree_id}/members`
  - `POST /api/v1/family-trees/{tree_id}/members`
  - `GET /api/v1/family-trees/{tree_id}/members/{member_id}`
  - `PATCH /api/v1/family-trees/{tree_id}/members/{member_id}`
  - `DELETE /api/v1/family-trees/{tree_id}/members/{member_id}`
- 固定关系接口：
  - `POST /api/v1/family-trees/{tree_id}/relationships/parent-child`
  - `DELETE /api/v1/family-trees/{tree_id}/relationships/parent-child`
  - `POST /api/v1/family-trees/{tree_id}/relationships/marriages`
  - `PATCH /api/v1/family-trees/{tree_id}/relationships/marriages`
  - `DELETE /api/v1/family-trees/{tree_id}/relationships/marriages`
  - `GET /api/v1/family-trees/{tree_id}/relationships/members/{member_id}/parents`
  - `GET /api/v1/family-trees/{tree_id}/relationships/members/{member_id}/children`
  - `GET /api/v1/family-trees/{tree_id}/relationships/members/{member_id}/spouses`
- 固定成员列表返回结构：
  - `items`
  - `total`
  - `page`
  - `page_size`
- 固定成员列表字段：
  - `member_id`
  - `tree_id`
  - `name`
  - `gender`
  - `birth_date`
  - `death_date`
  - `is_alive`
  - `generation_no`
  - `generation_name`
- 固定成员详情在列表字段基础上增加：
  - `biography`
  - `created_at`
  - `updated_at`
- 固定关系写入规则：
  - 父母子女删除接口与创建接口使用相同字段结构
  - 婚姻关系统一由服务层规范成员顺序为 `member_id_1 < member_id_2`
  - 婚姻结束与状态调整使用 `PATCH /marriages`

输出物：

- 阶段四接口清单
- 请求响应模型清单
- 阶段四角色能力矩阵

完成定义：

- 前后端在开始阶段四编码前，对接口、字段、权限和删除规则无歧义。

## 6.2 工作包 B：成员模块后端闭环

目标：

- 让成员模块具备正式可运行的后端 CRUD 能力，并形成清晰的 router / service / repository 分层边界。

具体任务：

- 补齐 `backend/app/schemas/member.py`：
  - `MemberCreateRequest`
  - `MemberUpdateRequest`
  - `MemberListItem`
  - `MemberDetailResponse`
  - `PaginatedMemberResponse`
- 改造 `backend/app/repositories/member_repository.py`，至少提供：
  - 按 `tree_id` 分页查询成员
  - 按 `tree_id + member_id` 查询成员
  - 统计族谱成员数
  - 创建成员
  - 更新成员
  - 删除成员
- 补齐 `backend/app/services/member_service.py`，承接：
  - 输入规范化
  - 业务校验
  - 统一响应模型拼装
  - 成员不存在时的 `404`
  - 非法输入时的 `400`
- 改造 `backend/app/api/routers/members.py`：
  - 读取接口统一接入 `require_tree_reader`
  - 写接口统一接入 `require_tree_editor`
  - 使用统一 `response_model`

成员字段校验固定为：

- `name` 去首尾空格后不能为空
- `gender` 只允许 `male`、`female`、`unknown`
- `generation_no` 为空或正整数
- `death_date >= birth_date`
- `is_alive = true` 时 `death_date` 必须为空
- `biography`、`generation_name` 允许为空，保存前去首尾空格并将空字符串转为 `null`

成员列表固定策略：

- 支持 `page`、`page_size`
- 默认排序：`generation_no ASC NULLS LAST, birth_date ASC NULLS LAST, member_id ASC`

删除规则：

- 工作包 B 先实现成员物理删除闭环。
- 若成员尚无关系记录，应直接删除成功。
- 若后续工作包 C、D 已接入关系数据，再由后续工作包补齐删除前关系清理规则。

输出物：

- 成员 schema 设计
- 成员 repository 与 service 职责边界
- 成员 CRUD 接口

完成定义：

- 路由层只负责收参、鉴权和调服务，成员业务逻辑不散落在路由层。

## 6.3 工作包 C：父母子女关系闭环

目标：

- 为阶段五递归查询和树形预览提供正式可维护的父母子女关系入口。

具体任务：

- 补齐父母子女关系创建、删除、读取接口。
- 固定 `parent_role` 只允许 `father` 或 `mother`。
- 拒绝以下场景：
  - 跨族谱关系
  - 重复父亲或重复母亲
  - 自环关系
  - 父母出生日期晚于或等于子女出生日期
  - 祖先环路

## 6.4 工作包 D：婚姻关系闭环

目标：

- 为配偶查询和亲缘路径图提供正式婚姻关系入口。

具体任务：

- 补齐婚姻创建、更新、删除、读取接口。
- 婚姻关系字段至少覆盖：
  - `member_id_1`
  - `member_id_2`
  - `married_at`
  - `ended_at`
  - `status`
- 拒绝以下场景：
  - 自环婚姻
  - 跨族谱婚姻
  - 重复婚姻
  - `ended_at < married_at`
  - `status = active` 但 `ended_at` 非空
  - `status = ended` 但 `ended_at` 为空

## 6.5 工作包 E：权限与删除规则统一

目标：

- 让成员与关系模块完全复用阶段三的族谱访问基线，避免出现新模块绕开权限体系。

具体任务：

- 所有成员与关系读取接口要求 `require_tree_reader`
- 所有成员与关系写接口要求 `require_tree_editor`
- 阶段四不引入 `creator` 专属成员/关系能力
- 明确成员删除、关系删除与族谱删除三者边界

## 6.6 工作包 F：前端成员页最小联调

目标：

- 让阶段四不仅有后端接口，也有最小可演示的成员入口。

具体任务：

- 改造 `frontend/src/stores/member.ts`
- 实现 `MemberListView.vue`
- 实现 `MemberDetailView.vue`
- 保持不同角色在前端的按钮可见性与后端权限一致

## 6.7 工作包 G：阶段四测试数据、自动化测试与联调说明

目标：

- 为阶段四建立稳定、可复用、能承接阶段五的数据基线。

具体任务：

- 提供阶段四种子数据脚本
- 增加成员与关系 API 自动化测试

- 固定验证命令、联调账号和数据拓扑

## 7. 推荐执行顺序

建议按以下顺序推进：

1. 工作包 A：成员与关系接口契约收口
2. 工作包 B：成员模块后端闭环
3. 工作包 C：父母子女关系闭环
4. 工作包 D：婚姻关系闭环
5. 工作包 E：权限与删除规则统一
6. 工作包 F：前端成员页最小联调
7. 工作包 G：测试数据、自动化测试与联调说明

原因：

- 先固定接口和规则，再写代码，能减少返工。
- 成员对象是关系模块的前提，必须先闭环。
- 前端联调应在接口、错误码和权限边界基本稳定后接入。

## 8. 阶段四验收标准

### 8.1 成员接口验收

- `GET /members` 可按分页返回成员列表。
- `POST /members` 可成功创建成员。
- `GET /members/{member_id}` 可返回成员详情。
- `PATCH /members/{member_id}` 可按角色规则更新成员。
- `DELETE /members/{member_id}` 可按角色规则删除成员。

### 8.2 关系接口验收

- 父母子女关系可创建、删除、读取。
- 婚姻关系可创建、更新、删除、读取。
- 非法关系、重复关系、自环关系、跨族谱关系与时间顺序错误都被拒绝。

### 8.3 权限边界验收

- 所有已登录用户都可读取成员与关系。
- `creator` 与 `collaborator` 可维护成员与关系。
- `reader` 及未显式授权但已登录用户只能读取。
- 未登录用户不可访问成员与关系接口。

### 8.4 文档与测试验收

- 阶段四接口、字段、权限、删除规则、测试命令有文档说明。
- 自动化测试覆盖成功路径、越权路径和关键边界路径。
- 阶段四边界明确，不混入搜索、递归查询、统计分析等后续业务实现。

## 9. 测试计划与用例

### 9.1 成员列表与详情测试

- 验证不同角色均可读取成员列表与详情。
- 验证分页与默认排序稳定。

### 9.2 成员创建与更新测试

- 验证 `creator` 与 `collaborator` 可创建、修改。
- 验证 `reader` 被拒绝。
- 验证空名称、非法性别、生卒冲突、在世成员带死亡日期等输入被拒绝。

### 9.3 成员删除测试

- 验证编辑角色可删除无关系成员。
- 验证读者删除被拒绝。

### 9.4 父母子女关系测试

- 验证合法父母关系写入成功。
- 验证重复父亲/母亲、自环、跨族谱、出生顺序错误被拒绝。
- 验证祖先环路触发器生效。

### 9.5 婚姻关系测试

- 验证合法婚姻创建成功。
- 验证婚姻结束与状态更新成功。
- 验证重复婚姻、自环、日期顺序错误与状态冲突被拒绝。

### 9.6 前端手工联调测试

- 验证成员列表页展示。
- 验证成员详情页展示。
- 验证编辑角色可创建成员。
- 验证只读角色无写按钮或写入被明确拒绝。
