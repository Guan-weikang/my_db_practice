# 阶段四：测试数据与联调说明

## 1. 目标

本文档用于固定阶段四的联调测试环境准备方式，确保成员与关系模块的后端验证、前端联调和演示都基于同一组稳定数据。

## 2. 当前阶段约定

- 所有已登录用户默认可读取族谱、成员与关系。
- `creator` 与 `collaborator` 可写成员与关系。
- `reader` 与未显式授权但已登录用户只可读。
- 成员删除采用物理删除。
- 婚姻关系支持 `active` 与 `ended` 两种状态。

## 6. 建议验证顺序

### 5.1 后端自动化验证

执行：

```bash
pytest backend/tests -q
python -m compileall backend/app backend/tests
```

### 5.2 数据准备验证

- `stage3_creator` 登录后应能读取 `Stage3 Managed Tree` 全部成员并进行写操作
- `stage3_collaborator` 登录后应能读取并编辑 `Stage3 Managed Tree` 成员
- `stage3_reader` 登录后应能读取 `Stage3 Managed Tree` 成员但不能写入
- `stage3_viewer` 登录后应因默认可读规则读取 `Stage3 Managed Tree` 成员，但不能写入
- `Stage4 Isolated Member` 应可在成员详情页直接删除
- `Stage4 Ended Husband` / `Stage4 Ended Wife` 的婚姻应显示为 `ended`

### 5.3 手工联调验证

- 打开 `Stage3 Managed Tree` 的成员列表页
- 进入 `Stage4 Grandson` 或 `Stage4 Branch Son` 的成员详情页，确认父母、子女、配偶已展示
- 进入 `Stage4 Ended Husband` 的成员详情页，确认婚姻状态为 `ended`
- 进入 `Stage4 Isolated Member` 的成员详情页，执行成员删除
- 新增一个临时成员，验证成员创建与编辑
- 为新增成员建立一条父母子女关系，再执行关系删除
- 为新增成员建立一条婚姻关系，再执行 `ended` 更新和删除
- 用不同树成员尝试创建关系，确认跨族谱被拒绝

## 7. 手工验收关注点

- 不同角色的写按钮可见性是否正确
- 后端 403 是否与前端提示一致
- 成员详情是否能区分重名成员的 ID 与辈分信息
- 婚姻状态与时间字段是否保持一致
- 成员删除后列表是否正确刷新
- 删除 `Stage4 Isolated Member` 后，不应影响其他成员关系展示
- `Stage4 Grandson` 的父母展示应同时包含父系和母系
- `Stage4 Branch Son` 的子女展示应至少包含 `Stage4 Grandson` 与 `Stage4 Granddaughter`
