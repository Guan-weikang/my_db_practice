# 阶段四：测试数据与联调说明

## 1. 目标

本文档用于固定阶段四的联调测试环境准备方式，确保成员与关系模块的后端验证、前端联调和演示都基于同一组稳定数据。

## 2. 当前阶段约定

- 所有已登录用户默认可读取族谱、成员与关系。
- `creator` 与 `collaborator` 可写成员与关系。
- `reader` 与未显式授权但已登录用户只可读。
- 成员删除采用物理删除。
- 婚姻关系支持 `active` 与 `ended` 两种状态。

## 3. 联调账号

阶段四继续复用阶段三四个固定账号：

- `stage3_creator / Password123`
- `stage3_collaborator / Password123`
- `stage3_reader / Password123`
- `stage3_viewer / Password123`

## 4. 推荐种子数据拓扑

建议在阶段三数据基础上扩展以下成员与关系：

### 4.1 Stage4 Core Tree

用途：

- 成员列表、详情、创建、修改
- 父母子女创建与删除
- 婚姻创建、结束与删除

建议结构：

- 三代直系样例 1 组
- 孤立成员 1 个，用于删除测试
- 已婚配偶 1 对
- 已结束婚姻 1 对

### 4.2 Stage4 Cross Tree Sample

用途：

- 验证跨族谱关系创建被拒绝

建议结构：

- 至少 2 个来自不同族谱的成员 ID

## 5. 建议验证顺序

### 5.1 后端自动化验证

执行：

```bash
pytest backend/tests -q
python -m compileall backend/app backend/tests
```

### 5.2 数据准备验证

- `stage3_creator` 登录后应能读取目标树全部成员并进行写操作
- `stage3_collaborator` 登录后应能读取并编辑成员
- `stage3_reader` 登录后应能读取成员但不能写入
- `stage3_viewer` 登录后应因默认可读规则读取成员，但不能写入

### 5.3 手工联调验证

- 打开成员列表页
- 进入成员详情页
- 新增一个孤立成员
- 修改成员资料
- 创建父母子女关系
- 创建婚姻关系
- 将婚姻更新为 `ended`
- 删除孤立成员

## 6. 手工验收关注点

- 不同角色的写按钮可见性是否正确
- 后端 403 是否与前端提示一致
- 成员详情是否能区分重名成员的 ID 与辈分信息
- 婚姻状态与时间字段是否保持一致
- 成员删除后列表是否正确刷新

## 7. 与后续阶段的衔接

阶段四测试数据应保持小规模、强确定性，并为阶段五复用：

- 父母子女递归链路
- 配偶链路
- 多代成员样例
- 可验证空结果和异常结果的边界数据
