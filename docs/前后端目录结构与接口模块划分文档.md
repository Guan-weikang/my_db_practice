# 族谱管理系统前后端目录结构与接口模块划分文档

## 1. 文档目的

本文档用于明确族谱管理系统的前后端工程目录结构、模块职责和接口划分方式，作为后续实际项目初始化、多人协作和接口联调的设计依据。

本文档基于以下技术栈：

- 前端：Vue 3 + Vite + Vue Router + Pinia + Axios
- 后端：FastAPI + SQLAlchemy 2.0 + Pydantic v2 + Alembic
- 数据库：PostgreSQL
- 复杂查询：原生 SQL + Recursive CTE

## 2. 工程总体目录结构

推荐项目根目录结构如下：

```text
project-root/
  backend/
  frontend/
  docs/
  deploy/
  scripts/
  data/
  docker-compose.yml
  README.md
```

各目录职责如下：

- `backend/`：FastAPI 后端工程
- `frontend/`：Vue 前端工程
- `docs/`：需求、数据库、架构、接口等文档
- `deploy/`：Docker、Nginx、部署配置
- `scripts/`：数据生成、导入、初始化脚本
- `data/`：CSV、测试数据、导出数据等

## 5. 后端接口模块划分

后端接口建议按业务域拆分，而不是按数据库表机械拆分。

## 5.1 认证模块 `auth`

职责：

- 用户注册
- 用户登录
- 刷新令牌
- 用户登出
- 获取当前用户信息

建议路由前缀：

- `/api/v1/auth`

建议接口：

- `POST /register`
- `POST /login`
- `POST /refresh`
- `POST /logout`
- `GET /me`

## 5.2 用户模块 `users`

职责：

- 查询用户资料
- 修改用户基础信息

建议路由前缀：

- `/api/v1/users`

建议接口：

- `GET /{user_id}`
- `PATCH /me`

## 5.3 族谱模块 `family_trees`

职责：

- 族谱创建、列表、详情、修改、删除
- 获取当前用户可访问族谱

建议路由前缀：

- `/api/v1/family-trees`

建议接口：

- `GET /`
- `POST /`
- `GET /accessible`
- `GET /{tree_id}`
- `PATCH /{tree_id}`
- `DELETE /{tree_id}`

## 5.4 协作者模块 `collaborators`

职责：

- 邀请协作者
- 修改访问角色
- 撤销访问权限
- 查询协作者列表

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/collaborators`

建议接口：

- `GET /`
- `POST /`
- `PATCH /{user_id}`
- `DELETE /{user_id}`

说明：

- `access_role` 只允许 `collaborator` 或 `reader`
- `creator` 不通过该接口创建，而由族谱创建行为自动产生

## 5.5 成员模块 `members`

职责：

- 成员增删改查
- 成员基础信息维护
- 字辈字段维护

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/members`

建议接口：

- `GET /`
- `POST /`
- `GET /{member_id}`
- `PATCH /{member_id}`
- `DELETE /{member_id}`

成员字段重点包括：

- `name`
- `gender`
- `birth_date`
- `death_date`
- `generation_no`
- `generation_name`
- `biography`

## 5.6 关系模块 `relationships`

职责：

- 维护父母子女关系
- 维护婚姻关系
- 查询某成员的父母、子女、配偶

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/relationships`

建议接口：

- `POST /parent-child`
- `DELETE /parent-child`
- `POST /marriages`
- `DELETE /marriages`
- `GET /members/{member_id}/parents`
- `GET /members/{member_id}/children`
- `GET /members/{member_id}/spouses`

## 5.7 查询模块 `search`

职责：

- 姓名模糊查询
- 树形预览
- 分支查询

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/search`

建议接口：

- `GET /members`
- `GET /branch-tree`

说明：

- `GET /members` 支持关键词模糊检索
- `GET /branch-tree` 支持基于根成员的树形预览

## 5.8 统计分析模块 `analytics`

职责：

- Dashboard 数据
- 课程要求中的统计分析查询

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/analytics`

建议接口：

- `GET /dashboard`
- `GET /generation/max-average-lifespan`
- `GET /members/older-than-50-unmarried-male`
- `GET /members/before-generation-average-birth-year`

## 5.9 亲缘路径模块 `kinship`

职责：

- 祖先递归查询
- 两人亲缘路径查询

建议路由前缀：

- `/api/v1/family-trees/{tree_id}/kinship`

建议接口：

- `GET /ancestors/{member_id}`
- `GET /path`

说明：

- `GET /path` 通过查询参数传入两个成员 ID
- 内部使用原生 SQL + Recursive CTE

## 5.10 系统模块 `health`

职责：

- 健康检查
- 可用性探测

建议路由前缀：

- `/api/v1/health`

建议接口：

- `GET /`

## 7. 接口设计约定

## 7.1 基础约定

- API 前缀统一为：`/api/v1`
- 返回格式统一为 JSON
- 时间字段统一使用 ISO 8601
- 认证方式统一使用 Bearer Token

## 7.2 错误处理约定

建议统一错误响应结构：

```json
{
  "code": "FORBIDDEN",
  "message": "You do not have permission to modify this family tree.",
  "details": null
}
```

## 7.3 分页约定

对于列表查询，建议统一支持：

- `page`
- `page_size`

返回结果建议包含：

- `items`
- `total`
- `page`
- `page_size`

## 8. 目录与模块划分原则

本项目目录划分遵循以下原则：

1. 前后端都按职责分层，不按“所有东西堆在一起”的方式组织。
2. 复杂 SQL 与 ORM CRUD 分离。
3. 接口按业务域拆分，不按数据库表机械拆分。
4. 权限、认证、查询、统计作为独立模块看待。
5. 字辈、亲缘路径、递归查询这些业务特性必须在模块设计中有明确归属。

## 9. 建议的开发顺序

建议按以下顺序推进实现：

1. 后端基础工程与数据库连接
2. 用户认证模块
3. 族谱与协作者模块
4. 成员管理模块
5. 父母子女与婚姻关系模块
6. 搜索与树形预览模块
7. 祖先与亲缘路径查询模块
8. 统计分析模块
9. 前端联调与权限控制

## 10. 结论

本项目建议采用：

- 前端按 `views / components / stores / api / router` 分层
- 后端按 `api / services / repositories / queries / models / schemas` 分层
- 接口按认证、族谱、协作、成员、关系、搜索、统计、亲缘路径、健康检查等业务域拆分

这样做有三个直接好处：

1. 结构清晰，适合多人协作
2. 复杂查询与普通 CRUD 不会混乱耦合
3. 能直接支撑后续 Docker 化、接口联调、测试与课程报告整理
