# 阶段七：前端联调用接口文档

## 1. 文档目的

本文档用于说明阶段七大规模数据导入后，前端如何直接复用现有在线接口进行联调、展示和性能样例验证。

阶段七本身**没有新增 HTTP API**。  
前端仍然通过现有模块读取导入后的大规模数据：

- `family-trees`
- `members`
- `search`
- `kinship`
- `analytics`

阶段七新增的是：

- 规则生成的大规模数据
- `COPY` 导入脚本
- 分支导出脚本
- benchmark 性能脚本

这些脚本不直接提供浏览器调用接口，但其结果会影响前端联调时能看到的数据规模、树列表和查询表现。

## 2. 联调前提

### 2.1 后端接口基线

- API 前缀固定为 `/api/v1`
- 所有业务接口仍需登录后访问
- 默认沿用现有权限基线：
  - 创建者可读写
  - 协作者可按权限读写
  - 默认只读用户可读

### 2.2 阶段七数据导入后默认会出现的 10 棵树

在默认参数下，前端通过 `GET /api/v1/family-trees` 能看到以下 10 棵树：

1. `汉朝刘氏`
2. `唐朝李氏`
3. `明朝朱氏`
4. `吴越钱氏`
5. `孔氏`
6. `合成陈氏`
7. `合成王氏`
8. `合成张氏`
9. `合成林氏`
10. `合成赵氏`

默认 `tree_id` 起始为 `7001`，按生成顺序递增：

- `7001`：汉朝刘氏
- `7002`：唐朝李氏
- `7003`：明朝朱氏
- `7004`：吴越钱氏
- `7005`：孔氏
- `7006`：合成陈氏
- `7007`：合成王氏
- `7008`：合成张氏
- `7009`：合成林氏
- `7010`：合成赵氏

如果后续更改了生成参数或导入目标库，前端应以接口返回为准，不要在页面写死这些 ID。

### 2.3 阶段七联调账号

阶段七默认数据提供 3 个固定账号，密码均为 `Password123`：

- `stage7_importer`：10 棵族谱的创建者
- `stage7_collaborator`：10 棵族谱的协作者
- `stage7_reader`：10 棵族谱的只读用户

三类账号用于手工联调不同权限视角。创建者可管理族谱与协作者，协作者可执行成员维护类操作，只读用户用于验证只读页面和权限提示。

## 3. 推荐前端接口清单

## 3.1 族谱列表与详情

### 1. 获取可访问族谱列表

`GET /api/v1/family-trees?page=1&page_size=20`

用途：

- Dashboard 族谱切换下拉框
- 族谱列表页
- 阶段七大树入口发现

返回结构：

```json
{
  "items": [
    {
      "tree_id": 7005,
      "tree_name": "孔氏",
      "surname": "孔",
      "compiled_at": "2026-05-13",
      "description": "Fully synthetic Kong-themed large benchmark tree.",
      "access_role": "reader"
    }
  ],
  "total": 10,
  "page": 1,
  "page_size": 20
}
```

### 2. 获取族谱详情

`GET /api/v1/family-trees/{tree_id}`

用途：

- 族谱详情页
- 查询页入口
- Dashboard 跳转当前族谱详情

## 3.2 成员列表与详情

### 3. 获取成员分页列表

`GET /api/v1/family-trees/{tree_id}/members?page=1&page_size=20`

用途：

- 阶段七大规模成员列表展示
- 分页和滚动性能联调

注意：

- 阶段七大树成员很多，前端不要默认一次性加载全量
- 当前前端 `fetchMembers(treeId)` 还没有传分页参数；若要更稳定联调，建议后续把分页参数补到前端封装里

### 4. 获取成员详情

`GET /api/v1/family-trees/{tree_id}/members/{member_id}`

用途：

- 成员详情页
- 从搜索结果、树查询、亲缘路径点击跳转

成员详情关键字段：

- `birth_date`
- `death_date`
- `is_alive`
- `generation_no`
- `generation_name`
- `biography`

阶段七数据保证：

- 所有成员都有 `birth_date`
- 所有死者都有 `death_date`

## 3.3 搜索与树查询

### 5. 姓名模糊搜索

`GET /api/v1/family-trees/{tree_id}/search/members?keyword=朱德&page=1&page_size=20`

用途：

- 验证大树下模糊搜索可用性
- 验证重名展示
- 搜索结果跳转成员详情

请求参数：

- `keyword`：至少 2 个字符
- `page`
- `page_size`

返回关键字段：

- `member_id`
- `name`
- `gender`
- `birth_date`
- `death_date`
- `is_alive`
- `generation_no`
- `generation_name`
- `father_name`
- `mother_name`

### 6. 分支树预览

`GET /api/v1/family-trees/{tree_id}/search/branch-tree?root_member_id=1018001&max_depth=4`

用途：

- 展示大树下某根成员的后代分支
- 验证阶段七导入后树结构仍可被前端消费

请求参数：

- `root_member_id`
- `max_depth`：默认 `4`，范围 `1-10`

返回关键字段：

- `root_member`
- `nodes[].depth`
- `nodes[].parent_member_id`
- `nodes[].incoming_parent_role`
- `nodes[].path_member_ids`

## 3.4 祖先与亲缘路径

### 7. 祖先查询

`GET /api/v1/family-trees/{tree_id}/kinship/ancestors/{member_id}?max_depth=30`

用途：

- 大树中向上追祖
- 验证深代链展示

### 8. 亲缘路径查询

`GET /api/v1/family-trees/{tree_id}/kinship/path?member_a=...&member_b=...&max_depth=12&include_ended_marriages=false`

用途：

- 大数据量下验证路径查询结果结构仍可展示
- 验证 `nodes + edges` 渲染

## 3.5 Dashboard 统计接口

### 9. Dashboard 汇总

`GET /api/v1/family-trees/{tree_id}/analytics/dashboard`

用途：

- 阶段七大树统计卡片

返回关键字段：

- `summary.total_members`
- `summary.male_count`
- `summary.female_count`
- `summary.unknown_count`
- `summary.male_ratio`
- `summary.female_ratio`

### 10. 平均寿命最长的一代

`GET /api/v1/family-trees/{tree_id}/analytics/generation/max-average-lifespan`

### 11. 超过 50 岁且没有配偶的男性成员

`GET /api/v1/family-trees/{tree_id}/analytics/members/older-than-50-unmarried-male`

默认阶段七数据中，10 棵族谱均保留 5 名超过 50 岁且无婚姻记录的男性成员，便于前端稳定展示该统计列表。

### 12. 出生年份早于本代平均出生年份成员

`GET /api/v1/family-trees/{tree_id}/analytics/members/before-generation-average-birth-year`

用途：

- 阶段七大规模数据下验证 Dashboard 四个区块都能正常加载

## 4. 推荐前端联调路径

推荐按下面顺序联调：

1. 登录
2. 请求 `GET /family-trees`
3. 进入 `tree_id = 7005` 的孔氏树
4. 打开 Dashboard：
   - 验证 `analytics` 四个接口
5. 打开成员搜索页：
   - 例如搜索 `孔德`、`朱德`
6. 打开分支树页：
   - 使用第 1 代根成员做 `branch-tree`
7. 打开祖先页和亲缘页：
   - 验证结构展示是否稳定

## 6. 前端特别注意事项

### 6.1 不要一次性拉全量成员

阶段七的孔氏树为 55,000 成员。  
前端必须通过分页、搜索或按需查询来获取成员，不能把整棵树的全量成员先拉到浏览器。

### 6.2 模糊搜索关键字要尽量具体

过宽关键字例如：

- `孔`
- `朱`

虽然能返回结果，但不利于界面展示和性能观察。推荐更具体的关键字：

- `孔德`
- `朱德`
- `王仁`

### 6.3 根成员导出与分支树不是一回事

- `export_branch.py` 是离线导出脚本
- `search/branch-tree` 是在线接口

前端只消费在线接口，不直接依赖导出脚本。

### 6.4 benchmark 不是前端 API

`benchmark_explain.py` 生成的是报告文件，不是浏览器调用接口。  
如果前端需要展示性能结果，应读取后端后续新增的报告展示接口，或者手工展示生成好的 Markdown / 截图。当前阶段前端不直接接这个脚本。
