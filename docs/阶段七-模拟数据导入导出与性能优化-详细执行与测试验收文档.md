# 阶段七：模拟数据、导入导出与性能优化详细执行与测试验收文档

## 1. 文档目的

本文档用于细化《[寻根溯源族谱管理系统-总开发计划](/home/mochen/db_practice/docs/寻根溯源族谱管理系统-总开发计划.md)》中的“阶段七：模拟数据、导入导出与性能优化”，作为阶段七实施、联调与验收的直接依据。

本文档默认承接以下前提：

- 阶段一至六已完成基础工程、权限、成员关系、复杂查询和 Dashboard 统计闭环。
- 阶段五、六已形成稳定的小规模功能测试数据基线。
- 阶段七新增的数据集用于性能基准和导入导出验证，不替代阶段四至六的小规模确定性测试集。

## 2. 阶段目标

本阶段的目标是让“十万级数据、批量导入导出、索引前后性能对比”成为正式可复现能力，具体包括：

- 生成满足课程要求的大规模数据集
- 建立“真实种子谱系 + 合成扩展”的混合数据方案
- 完成 CSV 产物生成
- 完成 PostgreSQL `COPY` 导入方案
- 完成某个分支数据导出方案
- 完成姓名模糊查询和四代查询的索引前后 `EXPLAIN ANALYZE`

## 3. 范围与边界

### 3.1 本阶段范围

- 阶段七数据来源白名单与真实性边界说明
- 真实种子谱系 manifest
- 大规模数据生成器
- CSV 数据产物
- `COPY` 导入脚本与导出脚本
- 性能对比脚本与性能说明

### 3.2 本阶段不做

- 不建设权威历史家谱数据库
- 不做大规模 OCR 家谱识别
- 不引入全文搜索引擎
- 不做在线后台任务调度系统
- 不修改现有业务表结构来持久化 provenance

## 4. 阶段七固定业务规则

- 阶段七同时保留两套数据基线：
  - 阶段四至六小规模确定性联调数据
  - 阶段七大规模性能数据
- 阶段七真实信息只保留在“知名人物种子层”
- 真实种子层以 sidecar manifest 形式保存，不直接宣称为完整真实全谱
- 生成扩展成员全部标记为生成节点，只在 sidecar provenance 中区分
- 至少生成 10 个族谱
- 至少 1 个族谱拥有 50,000 以上成员
- 总成员数不少于 100,000
- 每棵树至少 30 代传承
- 每个成员至少与另一个成员存在亲缘或婚姻关系，不生成孤立性能节点
- 性能验证固定围绕：
  - 姓名模糊查询
  - 四代查询

## 5. 交付物

本阶段完成后，至少应产出以下成果：

1. 阶段七数据来源与真实性边界说明
2. 5 棵真实种子树 manifest
3. 10 棵族谱的大规模数据生成脚本
4. 生成后的 CSV 数据目录
5. `COPY` 导入脚本或导入说明
6. 分支数据导出脚本或导出说明
7. 索引前后性能对比脚本与 `EXPLAIN ANALYZE` 输出
8. 阶段七测试与验收说明

## 6. 详细执行任务

## 6.1 工作包 A：数据来源白名单与真实性边界收口

目标：

- 固定阶段七可接受的数据来源、不可接受的数据来源和真实信息的保留边界。

具体任务：

- 输出阶段七来源白名单文档
- 固定 `Wikidata` 与 `CBDB` 为优先结构化来源
- 固定 `FamilySearch Chinese Genealogy`、`上海图书馆家谱检索` 等为人工校验参考来源
- 固定不做扫描版家谱 OCR 批量入库
- 固定不做无授权整站抓取
- 固定真实人物只保留在种子层，其余成员由生成器扩展

完成定义：

- 数据来源、许可证边界和真实性边界无歧义，后续实现不再临时换策略。

## 6.2 工作包 B：真实种子树 manifest

目标：

- 为 5 棵名门族谱建立首批可校验、可扩展的真实种子谱系骨架。

具体任务：

- 固定纳入：
  - 汉朝刘氏
  - 唐朝李氏
  - 明朝朱氏
  - 吴越钱氏
  - 孔氏
- 每棵树先落少量高知名度历史人物
- 每个 seed manifest 至少包含：
  - 树编码与展示名
  - 姓氏
  - 种子成员列表
  - 父母关系列表
  - 婚姻关系列表
  - 来源系统与来源 URL
  - 真实性与置信度标记
- 提供 manifest 校验脚本和 manifest 索引文件

完成定义：

- 5 棵树都拥有结构合法、可被生成器读取的 seed manifest。

## 6.3 工作包 C：大规模数据生成器

目标：

- 把真实种子树扩展成满足课程规模的数据集，同时保持结构合法和性能测试友好。

具体任务：

- 在 `scripts/stage7/` 下落地生成器模块
- 读取 seed manifest
- 固定输出不少于：
  - `user_account.csv`
  - `family_tree.csv`
  - `tree_collaborator.csv`
  - `member.csv`
  - `parent_child.csv`
  - `marriage.csv`
  - `member_provenance.csv`
- 固定默认树规模分配：
  - 孔氏 50,000
  - 朱氏 12,000
  - 李氏 10,000
  - 刘氏 8,000
  - 钱氏 5,000
  - 陈氏 4,000
  - 王氏 3,500
  - 张氏 3,000
  - 林氏 2,500
  - 赵氏 2,000
- 固定默认总代数：
  - 所有树至少 30 代
  - 孔氏固定 40 代
- 固定生成约束：
  - 不生成跨树关系
  - 不生成父母自环
  - 每个子节点最多 1 父 1 母
  - 婚姻主键顺序始终满足 `member_id_1 < member_id_2`
  - 保留一定比例重名成员

完成定义：

- 在默认参数下可生成满足课程规模要求的完整 CSV 数据集。

## 6.4 工作包 D：COPY 导入与分支数据导出

目标：

- 让阶段七不只有 CSV 文件，还能完成可复现导入和指定分支导出。

具体任务：

- 提供 PostgreSQL `COPY` 导入命令或脚本
- 约定导入顺序：
  - `user_account`
  - `family_tree`
  - `tree_collaborator`
  - `member`
  - `parent_child`
  - `marriage`
- 提供按 `tree_id + root_member_id` 导出的分支数据脚本

完成定义：

- 导入导出流程可复现且能生成独立文件。

## 6.5 工作包 E：索引与性能验证

目标：

- 为课程报告提供清晰、可复述的索引前后性能对比证据。

具体任务：

- 对姓名模糊查询执行索引前后 `EXPLAIN ANALYZE`
- 对四代查询执行索引前后 `EXPLAIN ANALYZE`
- 固定对比对象：
  - `idx_member_name_trgm`
  - `idx_parent_child_tree_parent`
- 固定输出内容：
  - 测试 SQL
  - 索引 SQL
  - 执行计划
  - 建索引前后耗时对比

完成定义：

- 阶段七拥有完整性能对比证据，可直接进入实验报告。

## 6.6 工作包 F：测试数据、自动化测试与验收说明

目标：

- 为阶段七建立稳定的大规模数据校验口径，避免只验证“脚本能跑完”。

具体任务：

- 为 seed manifest 提供结构校验
- 为生成器提供小规模快速测试
- 为最终 CSV 提供计数校验
- 为导入导出流程提供完整性校验
- 为性能实验提供复测脚本与说明

完成定义：

- 阶段七所有离线能力具备自动化校验和可复述验收口径。

### 8.3 导入导出验收

### 8.4 性能验收

- 性能基准复测说明存在

## 9. 测试计划与用例

### 9.1 Seed Manifest 测试

- 验证 5 棵树 manifest 全部可读
- 验证成员编码无重复
- 验证父母与婚姻关系引用合法

### 9.2 生成器测试

- 验证小规模参数下可成功生成完整 CSV
- 验证不会产生跨树关系、自环关系和非法婚姻排序
- 验证真实种子成员在生成结果中被保留

### 9.3 数据规模测试

- 验证默认配置下总成员数达标
- 验证孔氏树规模达标
- 验证代数达标

### 9.4 导入导出测试

- 验证导入顺序可执行
- 验证导入后计数与 CSV 一致
- 验证分支导出结果闭包完整

### 9.5 性能测试

- 验证姓名模糊查询索引前后对比
- 验证四代查询索引前后对比
- 验证结果可形成课程报告材料
