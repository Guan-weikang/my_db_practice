# 阶段七：测试数据、联调、导入导出与性能复测说明

## 1. 目标

本文档用于固定阶段七的大规模数据准备方式、导入导出流程和性能复测口径，确保阶段七结果可重复、可展示、可写入实验报告。

## 2. 当前阶段约定

- 阶段七新增的是“性能基准数据集”，不替换阶段四至六的小规模联调数据。
- 真实历史信息只保留在 5 棵 seed manifest 的种子层。
- 大多数成员由生成器扩展产生，不宣称为真实历史人物。
- 导入方式固定使用 PostgreSQL `COPY`。
- 性能对比固定围绕：
  - 姓名模糊查询
  - 四代查询

阶段七当前提供以下脚本：

- [generate_dataset.py](/home/mochen/db_practice/scripts/stage7/generate_dataset.py)

## 4. 建议执行顺序

### 4.1 校验 seed manifest

```bash
python scripts/stage7/build_seed_manifests.py
```

预期结果：

- `data/stage7/seeds/manifest_index.json` 被更新
- 输出显示已校验 5 个 seed manifest

### 4.2 生成大规模 CSV

```bash
python scripts/stage7/generate_dataset.py
```

默认输出目录：

- [data/stage7/generated](/home/mochen/db_practice/data/stage7/generated)

预期结果：

- `family_tree.csv`
- `member.csv`
- `parent_child.csv`
- `marriage.csv`
- `user_account.csv`
- `tree_collaborator.csv`
- `member_provenance.csv`

### 4.3 使用 COPY 导入

```bash
export DATABASE_URL='postgresql://...'
python scripts/stage7/import_copy.py
```

固定导入顺序：

1. `user_account`
2. `family_tree`
3. `tree_collaborator`
4. `member`
5. `parent_child`
6. `marriage`

### 4.4 导出指定分支

```bash
export DATABASE_URL='postgresql://...'
python scripts/stage7/export_branch.py --tree-id 7001 --root-member-id 1000001
```

默认输出目录：

- `data/stage7/exports/tree_<tree_id>_root_<root_member_id>/`

输出文件：

- `member.csv`
- `parent_child.csv`
- `marriage.csv`

### 4.5 性能复测

```bash
export DATABASE_URL='postgresql://...'
python scripts/stage7/benchmark_explain.py --tree-id 7005 --keyword 孔德 --ancestor-member-id 1005001
```

默认输出目录：

- `data/stage7/reports/`

输出内容：

- 姓名模糊查询索引前/后执行计划
- 四代查询索引前/后执行计划

## 5. 建议验证口径

### 5.1 数据规模验证

- `family_tree.csv` 至少 10 行
- `member.csv` 至少 100000 行
- 至少 1 棵树拥有 50000 以上成员
- 每棵树代数至少 30

### 5.2 导入后计数验证

- 数据库中的 `family_tree`、`member`、`parent_child`、`marriage` 行数与 CSV 对齐
- `member_provenance.csv` 行数应与 `member.csv` 一致

### 5.3 导出闭包验证

- 分支导出的所有父子关系两端成员都存在于导出 `member.csv`
- 分支导出的所有婚姻关系两端成员都存在于导出 `member.csv`

### 5.4 性能验证

- `idx_member_name_trgm` 建立前后，模糊搜索计划应有变化
- `idx_parent_child_tree_parent` 建立前后，四代查询计划应有变化
- 报告中保留建索引前后两段 `EXPLAIN ANALYZE`
