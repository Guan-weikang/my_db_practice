## 3. 设计原则

阶段八前端定位为“面向演示和联调的族谱管理工作台”，不是营销页面。整体设计应保持安静、清晰、可扫描，重点服务反复操作、数据核对和复杂关系查询。

具体原则：

- 信息密度优先，避免大面积装饰性 Hero 和营销式卡片堆叠。
- 使用 `shadcn-vue` 组件和组合模式承载交互，不重复造基础控件。
- 所有业务列表默认分页，阶段七大树场景下不做全量加载。
- 搜索、分支树、祖先查询、亲缘路径均提供清晰的输入约束、加载状态、空状态和错误状态。
- 权限表现与后端一致：创建者、协作者、只读用户在按钮、表单、危险操作上应有明确差异。
- 视觉上使用中性底色、克制边框、少量品牌色和状态色，避免单色调界面。
- 桌面端优先优化管理台效率，移动端保证可用和不溢出。
- 前端页面不得出现技术实现性文字；说明、空状态、错误提示和按钮文案都应面向最终用户。
- 错误提示必须明显，优先使用 `Alert`、醒目的状态色和清晰的修复建议。

## 4. 信息架构

### 4.1 应用骨架

建议将当前顶部导航重构为 `AppShell`：

- 桌面端：左侧 `Sidebar` + 顶部上下文栏 + 主内容区。
- 移动端：顶部栏 + `Sheet` 抽屉导航。
- 顶部上下文栏固定展示当前族谱、访问角色、当前用户和退出入口。
- 主内容区使用统一宽度、统一页面标题、面包屑和页面操作区。
- 当前族谱上下文允许保存到 `localStorage`，用于刷新后恢复最近访问族谱。

核心导航：

1. Dashboard
2. 族谱
3. 成员
4. 查询
5. 协作者

其中“成员、查询、协作者”依赖当前 `tree_id`，没有当前族谱时应引导用户先选择族谱。

### 4.2 路由建议

现有路由可继续沿用，阶段八建议在不破坏后端联调的前提下整理页面入口：

## 5. 页面设计

### 5.1 认证页

目标：

- 保持登录和注册流程短路径。
- 清晰展示错误、加载中和 redirect 行为。
- 不引入复杂品牌页或图文 Hero。

建议组件：

- `Card`
- `Form`
- `Input`
- `Button`
- `Alert`
- `Separator`
- `Spinner`

交互要求：

- 登录和注册提交按钮在请求中禁用，并显示 `Spinner`。
- 后端错误使用 `Alert` 展示。
- 已登录用户进入认证页时沿用当前路由守卫跳转逻辑。
- 页面文案只描述用户操作与业务结果，不展示 Token、API、路由守卫等技术概念。

### 5.2 Dashboard

目标：

- 作为阶段七大规模数据演示的第一入口。
- 支持族谱切换，展示成员总量、性别比例、代际寿命和课程统计结果。
- 对慢接口提供局部加载状态，而不是整页阻塞。

建议布局：

- 顶部：族谱选择器、访问角色、刷新按钮、进入族谱详情按钮。
- 第一行：总人数、男性、女性、未知性别、男女比例 KPI。
- 第二行：性别比例图、平均寿命最长代际、阶段七数据说明摘要。
- 下方：两类列表型统计结果表格。
- Dashboard 固定使用图表，至少覆盖性别比例或成员构成；统计表格继续保留，便于核对数据。

建议组件：

- `Select`
- `Card`
- `Badge`
- `Chart`
- `Table`
- `Skeleton`
- `Empty`
- `Alert`
- `Button`

接口映射：

- `GET /api/v1/family-trees`
- `GET /api/v1/family-trees/{tree_id}/analytics/dashboard`
- `GET /api/v1/family-trees/{tree_id}/analytics/generation/max-average-lifespan`
- `GET /api/v1/family-trees/{tree_id}/analytics/members/older-than-50-unmarried-male`
- `GET /api/v1/family-trees/{tree_id}/analytics/members/before-generation-average-birth-year`

### 5.3 族谱列表与详情

目标：

- 族谱列表负责发现和进入。
- 族谱详情负责当前族谱的“工作台入口”。

族谱列表建议：

- 使用 `Table` 展示族谱名称、姓氏、编修日期、访问角色、操作。
- 使用 `Sheet` 创建族谱。
- 使用 `Badge` 表示访问角色。
- 空状态使用 `Empty`。

族谱详情建议：

- 顶部展示族谱名称、编号、姓氏、访问角色。
- 快捷操作区进入成员、搜索、分支树、祖先查询、亲缘路径、协作者。
- 编辑族谱使用 `Sheet`，仅对创建者和协作者开放。
- 删除空族谱使用 `AlertDialog` 二次确认。

接口映射：

- `GET /api/v1/family-trees`
- `GET /api/v1/family-trees/{tree_id}`
- 现有创建、更新、删除族谱接口沿用当前前端封装。

### 5.4 成员列表与详情

目标：

- 成员列表必须适配 55,000 成员级别数据。
- 成员详情承载编辑、关系维护和查询跳转。

成员列表建议：

- `fetchMembers` 前端封装补充 `page` 与 `page_size` 参数。
- 默认 `page_size = 20`，允许用户切换到 `50`。
- 使用 `Table` + `Pagination`，不做全量拉取。
- 搜索入口引导到成员搜索页，不在列表页做全局模糊搜索。
- 新增成员使用 `Sheet`，避免占用列表页面主空间。

成员详情建议：

- 基本信息使用 `Card` 和描述列表。
- 编辑成员使用 `Sheet` + `Form`。
- 父母子女、婚姻关系可使用 `Tabs` 分组。
- 删除成员、删除关系等危险操作使用 `AlertDialog`。

接口映射：

- `GET /api/v1/family-trees/{tree_id}/members?page=1&page_size=20`
- `GET /api/v1/family-trees/{tree_id}/members/{member_id}`
- 现有成员创建、更新、删除和关系维护接口沿用当前前端封装。

### 5.5 查询中心

目标：

- 将成员搜索、分支树、祖先查询、亲缘路径统一为“查询中心”体验。
- 每个查询页都能独立演示，同时保持输入、结果和错误状态一致。

成员搜索：

- 输入 `keyword`，至少 2 个字符。
- 使用 `InputGroup` 或 `Form` 组合搜索按钮。
- 结果使用 `Table`，展示姓名、性别、出生、死亡、代际、父母名称和详情入口。
- 重名成员通过成员编号、代际、父母名称区分。

分支树：

- 输入根成员 ID 和 `max_depth`。
- `max_depth` 使用 `Select` 或 `Slider` 限制在 `1-10`。
- 默认以结构化列表和缩进树展示，优先保证 4 层以内清晰可读。
- 节点支持跳转成员详情。

祖先查询：

- 输入成员 ID 和 `max_depth`。
- 结果按 depth 分组，标识父亲、母亲路径。
- 数据为空时提示该成员没有可展示祖先链。

亲缘路径：

- 输入成员 A、成员 B、`max_depth` 和是否包含已结束婚姻。
- 结果以结构化列表展示链路节点和边标签。
- 无路径时使用 `Empty` 明确说明。

接口映射：

- `GET /api/v1/family-trees/{tree_id}/search/members?keyword=...&page=1&page_size=20`
- `GET /api/v1/family-trees/{tree_id}/search/branch-tree?root_member_id=...&max_depth=4`
- `GET /api/v1/family-trees/{tree_id}/kinship/ancestors/{member_id}?max_depth=30`
- `GET /api/v1/family-trees/{tree_id}/kinship/path?member_a=...&member_b=...&max_depth=12&include_ended_marriages=false`

### 5.6 协作者管理

目标：

- 让创建者清晰维护协作者。
- 只读用户和协作者看到明确权限提示。

建议组件：

- `Table`
- `Select`
- `Badge`
- `Dialog`
- `AlertDialog`
- `Alert`

交互要求：

- 添加协作者使用 `Dialog`。
- 修改权限使用 `Select`，保存成功后通过 `sonner` 通知提示。
- 移除协作者使用 `AlertDialog`。
- 非创建者不显示可操作控件，只显示 `Alert` 权限说明。

## 6. 组件与设计系统策略

### 6.1 shadcn-vue 初始化策略

阶段八实现时应先执行一次 `shadcn-vue init`，为项目建立：

- `components.json`
- Tailwind CSS 配置
- 全局 CSS 变量
- `components/ui/*`
- `lib/utils` 中的 `cn()` 工具
- 路径别名

推荐默认方向：

- 模板：`vite`
- 组件基础库：`reka`
- 图标库：固定为 `lucide-vue-next`
- 视觉预设：固定为 `nova`
- 审美方向：偏中式审美、清明式风格，整体清透、克制、留白明确，避免厚重仿古和装饰堆叠。

### 6.2 首批建议组件

MCP 生成的候选安装命令：

```bash
npm shadcn-vue add @shadcn/button @shadcn/card @shadcn/table @shadcn/pagination @shadcn/sidebar @shadcn/dialog @shadcn/alert-dialog @shadcn/form @shadcn/input @shadcn/select @shadcn/badge @shadcn/skeleton @shadcn/empty @shadcn/chart @shadcn/command @shadcn/tooltip @shadcn/tabs @shadcn/sheet @shadcn/separator @shadcn/alert @shadcn/sonner @shadcn/spinner
```

首批组件按优先级分为：

| 优先级 | 组件 | 用途 |
| --- | --- | --- |
| P0 | `button`, `card`, `form`, `input`, `select`, `alert`, `badge`, `spinner` | 表单、反馈、角色标识、基础操作、请求中状态 |
| P0 | `table`, `pagination`, `skeleton`, `empty`, `sonner` | 大数据列表、加载态、空状态、操作成功提示 |
| P0 | `dialog`, `alert-dialog`, `sheet` | 创建、编辑、危险操作、移动端导航 |
| P1 | `sidebar`, `separator`, `tabs`, `tooltip` | 应用骨架、详情页分组、辅助说明 |
| P1 | `chart` | Dashboard 性别比例和统计可视化 |
| P2 | `command` | 后续可扩展为族谱/成员快速跳转 |

### 6.3 组合规则

后续实现应遵守 `shadcn-vue` skill 中的关键规则：

- 表单使用 `FieldGroup`、`Field`、`FieldLabel`、`FieldDescription`。
- 选项数量在 2 到 7 个之间时优先使用 `ToggleGroup`。
- 加载占位使用 `Skeleton`，空数据使用 `Empty`，提示使用 `Alert`。
- 弹窗、抽屉和确认框必须提供可访问标题。
- 表格操作按钮使用图标和 tooltip 组合，危险操作必须二次确认。
- 状态颜色使用语义 token 和组件 variant，不直接散落业务色值。
- 间距统一使用 `gap-*` 组合，避免继续扩散当前手写样式。
- 创建和编辑类业务表单统一使用 `Sheet` 承载，列表和详情页保持可扫描。
- 图标固定使用 `lucide-vue-next`，按钮内图标需配合可访问标签或 tooltip。

## 7. 状态管理与数据流

### 7.1 Pinia store 建议

保留并整理现有 store：

- `auth`：登录态、用户、令牌恢复。
- `familyTree`：族谱列表、当前族谱、创建、更新、删除。
- `member`：成员列表、成员详情、创建、更新、删除。

阶段八建议新增或重构：

- `app`：当前布局状态、移动端侧栏开关、全局通知语义。
- `treeContext`：当前选中族谱 ID、访问角色、最近访问族谱。

不建议把所有查询结果都放入全局 store。成员搜索、分支树、祖先、亲缘路径属于页面级瞬时查询，优先使用页面 composable 管理局部状态。

当前选中族谱 ID 和最近访问族谱允许持久化到 `localStorage`。持久化数据仅作为前端体验优化，页面加载后仍以接口返回的权限和族谱状态为准。

### 7.2 API 封装建议

阶段八必须优先修正：

- [frontend/src/api/member.ts](/home/mochen/db_practice/frontend/src/api/member.ts:1) 的 `fetchMembers(treeId)` 增加 `page` 和 `page_size` 参数。

建议补充统一请求状态 composable：

- `useAsyncState` 或按现有风格实现轻量 `loading / error / data` 管理。
- 所有页面避免复制大量 `axios.isAxiosError` 解析逻辑。

## 8. 大数据与性能策略

阶段七默认孔氏树约 55,000 成员，阶段八前端必须按以下规则设计：

- 成员列表只分页加载，不做全量缓存。
- 搜索关键字至少 2 个字符，前端提交前校验。
- 搜索结果默认 `page_size = 20`。
- 分支树默认 `max_depth = 4`，允许调整到 `10`，但需要提示大深度可能较慢。
- 祖先查询默认 `max_depth = 30`。
- 亲缘路径默认 `max_depth = 12`。
- Dashboard 四个统计接口独立加载，单个接口失败不阻塞其他区块。
- 表格横向字段较多时，桌面端优先固定布局，移动端允许横向滚动。
- 分支树和亲缘路径第一版使用结构化列表和缩进树，不引入图形化节点图。

是否引入虚拟滚动暂不作为阶段八 P0。当前接口分页已能解决核心风险，虚拟滚动应等真实联调确认瓶颈后再评估。

## 9. 权限与交互状态

### 9.1 访问角色表现

| 角色 | 页面表现 |
| --- | --- |
| `creator` | 可编辑族谱、管理协作者、维护成员和关系、删除空族谱 |
| `collaborator` | 可编辑族谱、维护成员和关系，不可管理协作者 |
| `reader` | 可查看 Dashboard、族谱、成员、查询结果，不显示编辑和删除入口 |

### 9.2 通用状态

每个数据区块必须覆盖：

- 初始态
- 加载态
- 成功态
- 空态
- 错误态
- 无权限态

危险操作必须覆盖：

- 二次确认
- 请求中禁用
- 成功通知
- 失败 `Alert`

用户可见文案要求：

- 不出现 API、Token、路由、Pinia、store、组件名、接口名等技术实现性文字。
- 错误提示必须直接说明用户当前遇到的问题，例如“加载族谱失败，请稍后重试”。
- 权限提示应说明用户能做什么和不能做什么，例如“当前为只读权限，可查看信息但不能编辑”。
- 空状态应给出下一步动作，例如“暂无成员，可先新增一位成员”。

## 10. 视觉方向

阶段八采用 `nova` 风格，并向“清明式中式族谱档案工作台”调整：

- 背景：中性浅色，不使用大面积纯白。
- 主色：清透青绿或墨绿，用于主按钮、焦点和关键导航。
- 辅助色：墨灰、浅青、淡金和低饱和朱砂色，用于档案感、状态区分和轻量中式气质。
- 圆角：控制在 `6px-8px`，匹配管理台气质。
- 字体：以清晰中文阅读为主，默认先使用系统中文字体。
- 动效：只用于侧栏展开、弹窗进入、列表 hover 和通知提示，不做装饰性动效。
- 视觉边界：不做仿古纸张、印章堆叠、重纹理背景或大面积装饰图，避免影响数据阅读。

## 12. 已确认决策

以下决策已确认，阶段八实现时直接遵循：

1. 引入 Tailwind CSS，并逐步替换当前手写 `main.css`。
2. `shadcn-vue` 使用 `nova` 风格，并调整为偏中式审美、清明式风格。
3. 图标库固定为 `lucide-vue-next`。
4. Dashboard 使用图表。
5. 分支树和亲缘路径先按结构化列表和缩进树实现。
6. 成员创建、成员编辑、族谱创建、族谱编辑等业务表单统一使用 `Sheet`。
7. 当前族谱上下文允许保存到 `localStorage`。
8. 阶段八暂不引入 Playwright 测试，由人工手工联调。
9. 前端页面不出现技术实现性文字；说明性文字面向用户，错误提示必须明显。

## 13. 初步结论

阶段八可以以 `shadcn-vue` 为前端设计系统基础，对现有前端进行按需重构。优先级应放在应用骨架、分页列表、查询体验、权限状态和联调稳定性上；图形化树谱、命令面板、虚拟滚动等能力可以作为第二优先级，避免在阶段八第一轮实现中扩大风险。
