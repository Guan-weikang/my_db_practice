# 阶段五：搜索、树形预览、祖先查询与亲缘路径详细执行与测试验收文档

## 1. 文档目的

本文档用于细化《[寻根溯源族谱管理系统-总开发计划](/home/mochen/db_practice/docs/寻根溯源族谱管理系统-总开发计划.md)》中的“阶段五：搜索、树形预览、祖先查询与亲缘路径”，作为阶段五实施、联调与验收的直接依据。

本文档默认承接以下前提：

- 阶段一已固定统一错误结构、分页结构和测试基座。
- 阶段二已完成登录鉴权与族谱读写权限依赖。
- 阶段三已完成族谱模块、协作者模块以及“所有已登录用户默认可读族谱”的访问基线。
- 阶段四已完成成员 CRUD、父母子女关系维护、婚姻关系维护以及稳定测试数据基线。

## 2. 阶段目标

本阶段的目标是让“查人、看分支、追祖先、查亲缘”成为正式可用的只读查询能力，并为后续阶段的统计分析、性能测试和最终演示提供稳定入口，具体包括：

- 完成成员姓名模糊查询。
- 完成基于根成员的分支树形预览。
- 完成成员祖先递归查询。
- 完成两人亲缘路径查询。
- 补齐前端最小展示页面和导航入口。
- 建立阶段五自动化测试、手工联调与复用数据说明。

## 3. 范围与边界

### 3.1 本阶段范围

- 搜索模块接口与结果模型
- 亲缘查询模块接口与结果模型
- 原生 SQL 与 Recursive CTE 查询实现
- 查询参数校验、权限复用和结果整形
- 搜索页、分支树页、祖先页、亲缘路径页最小展示

### 3.2 本阶段不做

- 不实现 Dashboard 统计分析
- 不实现大规模性能专项优化
- 不引入 Redis 缓存、结果缓存或物化路径表
- 不引入可视化画布、拖拽树图或第三方图谱组件
- 不修改阶段四已落地的成员、父母子女、婚姻表结构
- 不扩展近亲婚配等新的业务约束体系

## 4. 阶段五固定业务规则

- 延续当前系统基线：所有已登录用户默认可读取族谱，因此也默认可读取该族谱下的搜索、树形、祖先和亲缘查询结果。
- 本阶段所有接口均为只读接口，统一接入 `require_tree_reader`。
- 每个族谱在查询语义上视为“混合无环图”：成员是节点，亲子关系是有向边，婚姻关系是无向边。
- 搜索、分支树和祖先查询仅依赖 `member` 与 `parent_child` 数据；不把婚姻关系混入树形结构。
- 亲缘路径查询同时使用 `parent_child` 与 `marriage` 两类关系构图。
- 分支树和祖先查询都属于“图上的受限子图查询”，但结果按层级视图组织，统一返回“路径展开的扁平节点列表”，不返回嵌套 JSON 树，避免多路径场景下丢失链路信息。
- 若同一成员通过多条合法路径到达，允许在树形结果中重复出现；这是显式保留谱系收敛信息，而非脏数据。
- 亲缘路径查询属于“两点之间的最短路径子图查询”，结果按图路径组织，正式返回 `nodes + edges`。
- 亲缘路径默认只纳入 `active` 婚姻；只有在显式传入 `include_ended_marriages=true` 时，才把 `ended` 婚姻纳入路径图。

## 6. 详细执行任务

## 6.1 工作包 A：查询接口契约与结果模型收口

目标：

- 在编码前固定阶段五的接口、查询参数、结果结构和权限边界，避免后续前后端联调时重复改口径。

具体任务：

- 固定搜索模块接口：
  - `GET /api/v1/family-trees/{tree_id}/search/members`
  - `GET /api/v1/family-trees/{tree_id}/search/branch-tree`
- 固定亲缘模块接口：
  - `GET /api/v1/family-trees/{tree_id}/kinship/ancestors/{member_id}`
  - `GET /api/v1/family-trees/{tree_id}/kinship/path`
- 固定所有查询接口统一接入 `require_tree_reader`
- 固定公共查询参数规则：
  - `keyword` 去首尾空格后长度至少 2，最大 50
  - `page` 默认 1
  - `page_size` 默认 20，最大 50
  - `branch-tree.max_depth` 默认 4，最小 1，最大 10
  - `ancestors.max_depth` 默认 30，最小 1，最大 100
  - `path.max_depth` 默认 12，最小 1，最大 20
  - `include_ended_marriages` 默认 `false`
- 固定错误行为：
  - 族谱不存在返回 `404`
  - 成员不存在或不属于该族谱返回 `404`
  - 空关键字、短关键字、非法分页或非法深度返回 `400`

输出物：

- 阶段五接口清单
- 查询参数清单
- 响应模型清单
- 阶段五读取权限矩阵
- “混合图模型 + 混合结果组织”设计说明

完成定义：

- 前后端对阶段五接口名、字段名、参数默认值和只读权限边界无歧义。

## 6.2 工作包 B：姓名模糊查询闭环

目标：

- 让同一族谱内的成员姓名模糊搜索成为正式功能，并能区分重名成员。

具体任务：

- 在 `backend/app/queries/search_queries.py` 中落地成员模糊查询 SQL
- 复用现有 `pg_trgm` 索引与 `member(tree_id, name)` 组合索引
- 查询固定限定 `tree_id`
- 固定排序优先级：
  - 完全匹配优先
  - 前缀匹配次之
  - 子串匹配再次之
  - 然后按 `generation_no ASC NULLS LAST, birth_date ASC NULLS LAST, member_id ASC`
- 搜索结果项固定返回：
  - `member_id`
  - `tree_id`
  - `name`
  - `gender`
  - `birth_date`
  - `death_date`
  - `is_alive`
  - `generation_no`
  - `generation_name`
  - `father_name`
  - `mother_name`
- `father_name` 与 `mother_name` 仅作为重名辅助字段；没有对应关系时返回 `null`
- 结果使用分页结构返回：`items`、`total`、`page`、`page_size`

实现分层固定为：

- `queries` 负责原生 SQL
- `services/search_service.py` 负责关键字规范化、分页参数校验和响应拼装
- `api/routers/search.py` 只负责收参、鉴权和调服务

完成定义：

- 输入关键字后可稳定返回匹配成员，并可通过父母姓名、辈分和生卒信息区分重名成员。

## 6.3 工作包 C：分支树形预览闭环

目标：

- 提供基于根成员向下展开的后代分支查询结果，为前端树形缩进展示提供正式数据源。

具体任务：

- 在 `backend/app/queries/search_queries.py` 或独立后代查询模块中实现 `WITH RECURSIVE` 分支树查询
- 固定仅沿 `parent_child.parent_member_id -> child_member_id` 向下递归
- 查询语义固定为“以根成员为起点的后代子图视图”
- 固定返回结构包含：
  - `root_member`
  - `max_depth`
  - `nodes`
- `root_member` 返回根成员基础信息
- `nodes` 每项固定字段：
  - `member_id`
  - `tree_id`
  - `name`
  - `gender`
  - `birth_date`
  - `death_date`
  - `generation_no`
  - `generation_name`
  - `depth`
  - `parent_member_id`
  - `incoming_parent_role`
  - `path_member_ids`
- 根节点也出现在 `nodes` 中，固定：
  - `depth = 0`
  - `parent_member_id = null`
  - `incoming_parent_role = null`
- 同一成员若通过两条合法父母链都可由根到达，允许在 `nodes` 中重复出现
- 查询顺序固定按 `path_member_ids` 的字典序输出，前端据此直接做缩进列表
- 本接口不额外返回通用 `edges`，避免前端为了树形展示再做一次图到层级视图的重组

完成定义：

- 指定根成员后，可得到层级稳定、顺序稳定、支持多代展开的后代子图层级视图结果。

## 6.4 工作包 D：祖先递归查询闭环

目标：

- 提供输入成员后向上追溯全部祖先的正式查询能力。

具体任务：

- 在 `backend/app/queries/ancestor_queries.py` 中落地祖先递归查询 SQL
- 固定仅沿 `parent_child.child_member_id -> parent_member_id` 向上递归
- 查询语义固定为“以目标成员为起点的祖先子图视图”
- 返回结构固定包含：
  - `start_member`
  - `max_depth`
  - `nodes`
- `start_member` 返回查询起点成员基础信息
- `nodes` 每项固定字段：
  - `member_id`
  - `tree_id`
  - `name`
  - `gender`
  - `birth_date`
  - `death_date`
  - `generation_no`
  - `generation_name`
  - `depth`
  - `child_member_id`
  - `parent_role`
  - `path_member_ids`
- 若同一祖先可通过多条链路到达，允许重复出现，不做按 `member_id` 去重
- 成员无父母关系时：
  - 返回合法 `start_member`
  - `nodes` 为空列表
- 本接口不额外返回通用 `edges`，避免前端为了祖先层级展示再做一次图到层级视图的重组

完成定义：

- 祖先查询支持不固定深度，且在双亲分叉场景下保留完整祖先子图层级视图。

## 6.5 工作包 E：亲缘路径查询闭环

目标：

- 提供任意两名成员之间是否存在关系链，以及最短链路的正式查询能力。

具体任务：

- 在 `backend/app/queries/kinship_queries.py` 中实现统一关系边展开与递归路径搜索
- 路径图固定由以下边组成：
  - `parent_child` 正向边，关系类型记为 `parent`
  - `parent_child` 反向边，关系类型记为 `child`
  - `marriage` 双向边，关系类型记为 `spouse`
- 默认只把 `active` 婚姻纳入图
- 当 `include_ended_marriages=true` 时，同时纳入 `ended` 婚姻
- 查询目标固定为“最短跳数路径”
- 若存在多条最短路径，按路径成员 ID 数组字典序选第一条，保证结果稳定
- 返回结构固定包含：
  - `exists`
  - `hop_count`
  - `nodes`
  - `edges`
- `nodes` 为按路径顺序排列的成员列表
- `edges` 为相邻节点之间的顺序边列表，每项固定字段：
  - `from_member_id`
  - `to_member_id`
  - `relation_type`
  - `parent_role`
  - `marriage_status`
- 当 `member_a == member_b` 时返回：
  - `exists = true`
  - `hop_count = 0`
  - `nodes` 仅包含该成员
  - `edges = []`
- 当不存在路径时返回：
  - `exists = false`
  - `hop_count = null`
  - `nodes = []`
  - `edges = []`

完成定义：

- 输入两名成员后，系统可稳定判断是否连通，并在连通时返回最短可展示链路。

## 7. 推荐执行顺序

建议按以下顺序推进：

1. 工作包 A：查询接口契约与结果模型收口
2. 工作包 B：姓名模糊查询闭环
3. 工作包 C：分支树形预览闭环
4. 工作包 D：祖先递归查询闭环
5. 工作包 E：亲缘路径查询闭环
6. 工作包 F：前端基础查询页与导航收口
7. 工作包 G：测试数据、自动化测试与手工验收说明

原因：

- 先固定接口和结果结构，再落地 SQL，可减少前后端返工。
- 搜索模块最简单，先闭环可提供首批查询能力与查询 schema 模板。
- 分支树和祖先查询都依赖父母子女关系递归，适合连续实现。
- 亲缘路径最复杂，放在树形与祖先查询后实现更稳妥。
- 前端联调应在查询接口和结果结构基本稳定后接入。

## 8. 阶段五验收标准

### 8.1 搜索接口验收

- `GET /search/members` 可按关键字返回模糊搜索结果。
- 搜索结果支持分页。
- 搜索结果能通过父母姓名、辈分和生卒信息区分重名成员。

### 8.2 树形与祖先接口验收

- `GET /search/branch-tree` 可返回基于根成员的多代后代链。
- `GET /kinship/ancestors/{member_id}` 可返回不固定深度祖先链。
- 树形和祖先结果顺序稳定、层级明确。
- 树形和祖先结果虽然源于图查询，但返回结构可直接支持前端缩进层级展示。

### 8.3 亲缘路径接口验收

- `GET /kinship/path` 可返回存在性判断。
- 当路径存在时可返回稳定的最短链路。
- 当路径不存在时可返回明确空结果。
- 亲缘路径结果正式包含 `nodes + edges`，可直接表达最短路径子图。

### 8.4 权限与边界验收

- 所有已登录用户都可读取阶段五查询结果。
- 未登录用户不可访问查询接口。
- 非法参数、无效成员和跨族谱成员访问被明确拒绝。

### 8.5 文档与测试验收

- 阶段五接口、字段、参数默认值、返回结构和测试命令有文档说明。
- 自动化测试覆盖成功路径、空结果路径和关键异常路径。
- 阶段五边界明确，不混入统计分析、性能专项和导入导出实现。

## 9. 测试计划与用例

### 9.1 搜索模块测试

- 验证同树内按姓名模糊搜索成功。
- 验证重名成员能通过辅助字段区分。
- 验证空结果返回空列表而非报错。
- 验证过短关键字被拒绝。

### 9.2 分支树测试

- 验证根成员向下递归多代成功。
- 验证 `max_depth` 截断生效。
- 验证无子女成员只返回根节点。
- 验证谱系收敛场景保留重复路径节点。

### 9.3 祖先查询测试

- 验证双亲分叉祖先链返回成功。
- 验证多代向上递归成功。
- 验证无祖先记录时返回空 `nodes`。
- 验证重复祖先路径保留。

### 9.4 亲缘路径测试

- 验证同一成员零跳路径。
- 验证父子、夫妻、姻亲混合路径。
- 验证无路径时返回 `exists = false`。
- 验证默认不纳入已结束婚姻。
- 验证显式开启后可纳入已结束婚姻。
